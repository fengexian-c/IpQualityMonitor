# 路由历史对比（2.8.1）

## 查看方式

1. 在“全部目标”选择目标，进入“路由历史”。最多三列并排对比可见路径，每一行使用实际 TTL 对齐。
2. 右上方已有的“近 24 小时 / 近 7 天”同时筛选延迟折线、路径观测点及原始记录。路径归类使用当前目标保留期内的记录，筛选不改变候选范围。
3. 列头选择路径；路径数量较多时使用路径目录分页。默认代表快照是该路径在当前范围内最近一次观测。不同列的 RTT 可能来自不同时间，以列头时间为准。
4. 点击时间轴某条路径对应的观测位置，该列会切换到距离点击时间最近的原始快照。图中橙色位置含时间推定记录，灰色为未归类。“其他 / 未归类”一行容纳未显示的路径及未知记录；点击其他路径的观测时会将其放入第一列。
5. 点击节点查看完整 IP 列表、参考来源、原始记录 ID 与网络环境。点击“查看本次原始探测”打开当前快照，“查看参考来源探测”打开提供参考的那次实测。来源可以在当前筛选之外，不需要扩大时间范围。
6. 原始详情中勾选“显示逐次探测明细”，再展开需要核对的跳，查看实际发送时间（毫秒）、初测/补测、地址、状态和 RTT。旧记录没有发送时间时明确标记未记录。默认不展开，以保留紧凑布局。

每行路径时间轴使用最多 240 个时间格，多条接近的观测可能落在同一格。路径观察次数显示在列头与记录列表；时间格数量不是探测次数，也不代表线路在两次观测之间始终保持不变。点击后以显示的精确快照时间为准。

## 归类规则

归类算法版本为 `route-history-2`。页面底部显示算法与数据版本。路径名称仅是当前目标的显示编号，不是运营商对物理线路的命名。

- 使用目标地址、探测协议、来源环境、探测参数、实际目标到达 TTL 和每跳原始回应 IP。IP 采用规范形式；城市、ASN、线路名称与 RTT 不参与路径身份比较。
- “签名匹配”表示可见观测模式相同，不表示所有未知节点都已证实相同。“部分相容”表示实测信息与分支条件相容。
- 按完成时间与稳定 ID 寻找首次有实测见证的分歧，平局按目标到达 TTL、跳号和规范地址决定。只有同一次探测实测满足全部父分支条件，才能为该分支建立子分支；不能拼接多份缺失记录自证一条路径。无冲突的互补观测仍可共列。
- 至少三个可见跳作为常规候选的保守筛选条件，不把它当作可信度百分比。全部跳都有回应的短路径可按相同签名归类；只有目标回应但前面路径不明、纯超时等情况不靠时间相近强行分组。
- A/B 在某跳有不同 IP，而本次该区分跳已探测且全部超时、其余信息相容时，在候选中选择距离最近的真实、可追溯依据。错误、不可达或未探测不走时间规则。最多相隔 24 小时，等距优先此前依据，再按稳定 ID 排序。显示“时间推定”。
- 已经实测出现多个不同 IP、同时相容于多个路径时，保留“多回应 / 无唯一归属”，不使用纯超时的最近列规则强行选一个地址。不会生成多跳 IP 集合的笛卡尔积。
- 时间推定不进入路径约束，也不能供下一条未知记录继续推定或续期。相同 A 在 A → B → A 中可以共用一列，但引用不能穿过中间已经识别的 B。

当前列是按现存原始记录计算的回溯结果。新增记录的首次判断由后台保存，包含实际计算时间、算法、输入版本、证据截止时间、状态、模式条件及来源。在线首次判断只使用不晚于该探测完成时刻的观测；判断时间不冒充发送时间。重启后首次处理的记录标为“重启补算”。2.8.0 及更早的记录没有留存判断，显示“当时归列未记录”，不伪造历史事实。

后续证据可改变回溯归属，但不会覆盖首次判断。模式、状态、来源变化分别显示“归属修正”“状态变化”“依据更新”。首次判断不是告警记录；原有告警继续独立使用原始探测，历史界面不追写或撤销当时告警。保留期删除证据或未来算法升级后，回溯结果可能变化。

## 补全与原始值

“历史参考”默认开启，仅为全部超时的已探测 TTL 提供参考。未探测、目标之后、本地探测错误和不可达均保持各自状态；有真实回应的单元格不被历史 IP 覆盖。

| 单元格内容 | 含义 |
| --- | --- |
| 普通 IP、RTT、回应数 | 该列代表快照中的真实回应；RTT 为该 IP 的有效回应均值 |
| 本轮补测 | 本次运行初测后补测得到的回应，原始详情保留阶段 |
| ◇ 历史参考 | 来自选中快照之前的真实观测 |
| ◇ 后续观测 | 回看历史时，来自选中快照之后的真实观测 |
| 时间推定 | 当前记录同时相容于其他路径，归列取最近真实依据 |
| RTT — | 本次没有实测 RTT，来源延迟只能在详情中按来源时间查看 |

例如 `回应 0/10 · 超时 10` 即使显示参考 IP，仍然表示本轮十次探测全部超时。参考不会改变本次回应数、延迟、丢包统计、到达状态或原始 JSON。

引用距离按两条历史快照的完成时间计算，最长 24 小时；不是按查看页面的今天计算。因此可以回看三天前、彼此相隔十分钟的观测。明确的停测、休眠/恢复、来源网络变化、参数变化或中间出现冲突证据会禁止跨越引用。连续超时不会刷新旧参考的时间。

默认共同非公网节点或全部未知段统一折叠并保留 TTL 范围。不同列的私网 IP 有差异、出现错误、存在参考或目标节点时不盲目隐藏。需要逐跳核对时勾选“显示全部节点”。定位注释来自已有缓存，可通过原始记录的注释入口查看/更新；定位数据的缓存有效期与路径参考的 24 小时限制相互独立。

## 数据和性能

数据库原始路由结构保持兼容，新探测增加可选的 `ProbeExecutionId`；共享一次探测的多份结果继承同一执行 ID。旧记录没有该字段时，不因 IP 相同或时间接近而随意去重。

后台串行分析服务使用独立 `route-analysis.db`，包含规范化缓存和不可被普通缓存重建覆盖的首次判断。原库增加轻量来源版本表和事务触发器，追踪路由/边界的增删改，不修改既有 JSON。来源 ID、变更版本和边界在同一个读取事务取得。新增或变更记录才解析原始 JSON，定期核对 ID 可找回遗漏通知、删除及源库恢复的变化。

仅一个活动目标的索引驻留在分析服务中；页面固定阅读时另外保留它正在阅读的版本。相同实测签名追加复用分支目录并重新检查受影响的时间推定；新结构、删除、乱序插入和边界变化从已规范化观测后台重建。首次判断保存失败会使分析降级，不会进入采样写入队列。旧数据首次缓存可能需要一些时间，期间探测继续。

离开页面、切换目标或隐藏到托盘会取消未完成的页面加载，后台监测和首次判断继续。完整原始快照只在打开详情时按 ID 读取，不为选择框预载 200 份完整记录。不要把分析库当作可随意删除的缓存：其中还保存首次判断。复制整个 `data` 目录进行迁移。

矩阵最多三列、64 个 TTL 行并复用控件；时间轴最多 4 × 240 个观测格；原始列表每页 100 条，路径选择每页 80 种。两种选择框均复用选项；原始列表在打开详情时才填充，未变化的矩阵文字不重复写入控件。引用搜索在后台完成，界面使用有限单元格缓存。注释只批量读取可见列所需 IP 的本地缓存，每个 IP 独立显示地区/线路。

选择旧快照或路径列后固定阅读，点击“更新至最新”恢复跟随。固定期间切换协议重读相应曲线，切换 24 小时 / 7 天仍使用同一截止时刻；注释/校准独立更新，收起的原始面板保持收起。“历史参考”和“显示全部节点”只改变呈现，不冻结页面。自定义日期范围留待后续版本。

所有保留记录的精简索引大小仍随数据量增长。大量空缺或独特路径的处理成本高于相同签名重复记录，不截断候选来伪装完整分析。实际功能、性能和原生运行数据见源码 `verification/route-history-2.8.1/`；有限压力测试不等同于无限期运行保证。

## 本地验证

完整测试：`./test.ps1`；仅归类与参考测试：`./test.ps1 -Selection route-history`。使用项目既有 `TCP_MONITOR_SMOKE_TEST` 和独立 `TCP_MONITOR_DATA_DIR` 运行原生界面自检，可验证矩阵、过滤、时间选择、范围切换和原始快照打开。自检运行时不要使用真实数据目录。

压力测试：`./test-route-memory.ps1 -PublishedDirectory <运行包目录> -Seconds 300`。脚本在 `artifacts` 下创建独立空目录，只生成合成路由，不连接公网；覆盖三目标、读历史、页面/范围/协议切换、托盘和模拟清理，记录 CSV，并自动退出测试进程，不使用强制 GC。

路由界面表示从当前设备观察到的可见模式；多路径、隧道、设备限速和未回应仍会限制实际拓扑的可见性。表中补全有来源，不意味着探测到了原本未回应的设备。
