# 2.7.1 内存修复与验证

日期：2026-09-11。修复源码：`src/TcpLatencyMonitor.App`。WinUI 3、.NET 10 NativeAOT；本次未修改核心探测、数据库格式、检测频率、路由策略或定位凭据。没有停止、重启或替换用户正在运行的 2.7.0。

## 修复内容

- 全部目标按 ProfileId 复用行、图表、按钮及文本。增删目标时调整结构；事件通过 ID 解析最新配置，删除时清理行索引。浅/深色画刷复用。
- 图表使用少量 Path，复用 PathGeometry、PathFigure 和 PointCollection，并原位修改变化的坐标；圆点使用复用的 EllipseGeometry。连续区间仍包含每个统计点；迷你图对孤立点单独画标记，失败点独立保留。全尺寸图保留采样点、原有刻度规则、最低/最高值和断线。
- 图表共用一个命中区域与工具提示，按鼠标位置定位原始统计桶；缩放、数据与选择变化合并为一次待执行绘制。
- 选择框的可空布尔状态、行位置、画刷及按钮内容/启用状态只在实际变化时赋值；工具提示固定持有一个 TextBlock，更新其 Text，避免逐次替换 Content 引发模板反复处理。关闭的悬浮提示仅缓存字符串，鼠标进入/打开时再写入可视文本；已打开的提示继续实时更新。隔离对照显示，这条更新路径会在整表复用后继续积累原生内存。
- 小时方块、对比图例、单目标汇总和最近记录复用；小时桶按数据、裁剪范围、名称与最终颜色判断是否需要更新，未变化的桶不再触发 UI 更新；点击读取最新时段数据。夏令时以日期加 UTC 偏移区分重复小时。提示对象及画刷复用；日期标题、图例和标签仅在实际变化时写入界面。
- 隐藏页面延迟绘制，切页立即应用有效缓存；托盘期间停止图形更新而继续采样和记录。异步结果检查目标、页面、协议与时间范围，防止旧结果覆盖新选择。侧栏当前目标状态继续刷新。

## 最终 EXE 的隔离验证

核心回归 **275 项通过**；最终 Windows 原生 UI **103 项通过**，包含新增的控件实例复用、目标删除清理、缓存切页、隐藏页不绘制、新配置按钮、移动时间窗口点击、零延迟、失败/本地错误、极值和断线检查。查看了实际渲染的浅色、深色、七天对比和特殊数据曲线截图。

以下单位 MiB，工作集与私有提交是不同指标，不相加。没有在测试过程中或结束时人为调用 GC，也没有清空工作集。

十目标测试在第 2500 次之后，工作集范围 **200.72–227.32 MiB**，私有提交范围 **190.61–218.25 MiB**。高频切页仍可能形成新的原生分配，不能据此宣称所有长期增长已完全消除；工作集下降也可能受系统回收影响，需同时看私有提交。正常刷新测试实际约 10.0 分钟。

与旧版的同类四目标 400 次离线刷新对照：2.7.0 工作集 121.52 → 814.38 MiB；第一阶段仅复用行/实例后 121.18 → 172.13 MiB；最终构建 108.74 → 122.12 MiB。最终四张迷你图总共约 20 个直接子元素，原版仅成功圆点就可超过 1100 个。

这些数字属于同一机器上的模拟 UI 负载。十目标压力测试每次更新曲线数据、最新采样时间/延迟和悬浮提示文字，并每 100 次在全部目标/对比间切换，包含七天、峰值、失败和未采样点；四目标对照使用相同的 289 点、25 个小时桶；固定总览与固定对比各验证 2000 次动态刷新，以区分持续刷新和页面切换。测试不向公网探测，不读用户历史。最终验收串行运行；此前两项并行测试提前退出且没有生成完成标记，未计入通过。压力脚本已修正重复导航，并与实际数据库一样将小时桶对齐整点。系统调度和工作集回收仍会影响绝对数值。

**未完成 4–8 小时真实网络负载长测。** 6000 次加速更新不能等同于相应时长的真实运行，也不能证明所有负载下都不存在泄漏。当前结果确认整表/图表重建与重复界面更新造成的高分配问题显著改善；不承诺正式使用固定占用某个数值。
