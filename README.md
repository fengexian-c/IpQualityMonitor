# IP 质量监控 2.7.1

Windows 多目标 IP 持续监控工具。支持 ICMP、TCP、双协议分别统计，路由历史、异常恢复和本地诊断包导出。沿用 WinUI 3、.NET 10 NativeAOT、SQLite、原生托盘、免安装发布方式。基础监测不依赖外部运行时、Nmap、抓包驱动、NextTrace 或 Docker。

## 开始使用

1. 完整解压 `IpQualityMonitor-v2.7.1-win-x64.zip` 到可写目录。
2. 双击 `IpQualityMonitor.exe`，点击“＋ 添加”，填写名称（可选）和厂家提供的 IPv4/IPv6 地址。
3. 检测方式保持 **ICMP · 只需 IP**，点击“开始监控”。默认每 5 秒一次，超时 3 秒。继续添加其他目标，各自独立运行；也可先保存设置，再“全部开始”。

厂家提供了明确可用的端口后，再选择 TCP 或 ICMP + TCP。双协议模式右上角可切换统计视图，两项结果单独计算。路由始终使用 ICMP，界面明确标识，不冒充 TCP 业务路径。首次打开不会探测任何预设公网地址。全新安装默认启用在线节点注释和自动注释新路由；开始监控后会向 ipwho.is 查询路由中的公网节点 IP，可在右上角“统一设置”关闭。

关闭窗口隐藏到托盘并继续监控。托盘单击打开窗口，右键可全部开始/暂停或退出。窗口“退出”结束程序。“下次打开后自动监控”不注册 Windows 开机启动。

2.7.0 新增 NextTrace 在线定位：优先使用有效的 v4 七天令牌，未配置、失效或过期时自动使用内置 v3 PoW 组件。移除“导入 NextTrace”“导入记录”和命令复制入口，保留手动校准。详见 [节点注释使用指南](docs/NODE-ANNOTATIONS.md)。

## 2.7.1 内存修复

全部目标改为按目标 ID 复用行、按钮和迷你图；单目标与对比图改用少量绘图路径，并复用几何集合、小时方块及提示。保留全部统计点、峰值、失败标记、无数据断线及原始时段提示。 未打开的提示只缓存文字，鼠标进入或打开时显示最新内容；未变化的日期、图例、按钮状态不重复写入界面。页面切换立即使用有效缓存；隐藏页面和托盘状态不重画图表，后台探测及记录继续。

从 2.7.0 升级时，先通过软件右上角“退出”关闭旧程序（关闭窗口只会隐藏到托盘），完整解压新版，再将旧版整个 `data` 目录复制到新版程序目录。复制整个目录可保留目标、检测历史、路由、定位缓存、手动校准及加密令牌。相同 Windows 用户下可继续使用已有令牌。数据库格式和检测频率未改变。发布 ZIP 与源码不含个人数据。

## 统一设置

右上角 **统一设置** 独立于目标选择，即使没有目标也可配置。检测间隔、超时、路由开关、路由间隔、最大跳数、单跳超时和整轮预算由所有目标共用；点击 **保存并应用所有目标** 后生效。运行中的目标短暂停止并按新参数继续；已暂停的目标保持暂停。新增及恢复的目标自动沿用保存的统一设置。

升级旧配置时，以原来选中目标的频率/路由参数初始化统一设置一次。保存配置前保留 `settings.json.before-global.bak`。超时影响统计口径，原超时对应的历史保留在“历史配置”中。名称、IP、端口、检测协议、异常阈值与下次打开自动监控仍可分别设置。

在线注释和自动注释开关位于同一页面，点击后立即生效；定位数据源、缓存周期与令牌在旁边的弹窗中保存。

## 定位数据源与每日缓存

1. 右上角 **统一设置** → **定位数据源 / NextTrace 令牌**，首选数据源选择 **NextTrace**。
2. 如需优先使用 v4，点击 **领取 / 刷新 v4 七天令牌**，在官方网页手动完成领取；复制令牌，回到软件粘贴并保存。留空沿用已有令牌；移除令牌后使用 v3 PoW。
3. 缓存刷新间隔默认 **24 小时**。开启“在线节点注释”和“自动注释新路由”后，新出现的公网 IP 立即排队；仅自动刷新最近 24 小时路由中出现过、且缓存已到期的旧 IP。不开启自动注释时，仅手动查看 / 补全时按需查询。

v4 与 v3 使用同一份 SQLite 缓存，多个目标和重启后共享。有效缓存不会因为换令牌或换传输方式而重新查询。后台每 30 秒检查一次待刷新项，单轮最多 20 秒；网络查询不阻塞 ICMP / TCP 探测。失败保留最近成功结果，并显示旧缓存 / 查询状态。

令牌有效期从服务端响应取得。首次粘贴时显示“待确认”，不会把一个已使用多日的令牌错误当作重新获得七天有效期。服务端拒绝令牌后，避免逐 IP 重试无效令牌；网络异常暂时回退 PoW。收到服务限流（429）时遵守冷却期、保留缓存，不通过另一传输反复请求。

NextTrace Token 以 Windows DPAPI 加密保存在 `data/nexttrace-token.dpapi`；IPinfo Token 同样单独加密保存。令牌不写入 settings.json、不放在命令行、不进入诊断包；只通过私有 stdin 传给定位组件，不落盘或写入组件日志。内置 `NextTraceGeoHelper.exe` 负责 v4 的标准 HTTPS 请求与 v3 PoW 定位，按需启动，两分钟空闲后退出；运行不需要另装 Go、.NET 或抓包驱动。

选中 NextTrace 时，优先显示它提供的节点地区，同时保留其他来源供核对。香港等只有省区字段的结果按省区显示，ASN 缺失不虚构，不能据此确认 GIA/GT。手动校准仍优先；历史探测和最早注释保留。旧版已经保存的校准继续有效，移除导入入口不会清空历史数据库。

ipwho.is 与 IPinfo Core 仍可选择。Core 需要城市接口权限，Lite 不提供城市；首选这两种来源时沿用原有分歧展示。所有来源默认刷新间隔改为 24 小时，旧的七天缓存按原查询时间判断是否需要更新。

NextTrace 组件使用 GPLv3 源码，随源码包提供对应源代码与依赖源码；许可及版本信息位于 `licenses/`。官方在线 API 的第三方使用权限与源码许可分开，使用需遵循服务方规则。本地集成和验证不表示已获得其对外服务授权。

### 从 2.5.0 / 2.6.x 升级

先退出旧程序，完整解压新版，再将旧目录中的 `data` **复制**到新版程序目录。保留旧目录作为升级前备份。沿用 v5 数据库并新增兼容的节点最后出现时间表，保留原有测量、路由及注释；从 2.5.0 升级仍包含既有的 v5 迁移。原有目标和在线注释偏好保留；频率/路由参数按上述规则迁移为统一设置。

## 多目标布局与操作

- 左侧目标列表：按名称或 IP 搜索，点击切换所查看的目标。切换、对比和查看旧配置都不会重启后台监测。
- 全部目标：每个目标一行，显示最新状态、RTT、近 1 小时 P95、所选时段失败比例/样本量、趋势和最新路由的已识别城市/线路。路由使用实际快照时间，城市为可见节点的 IP 定位，不代表完整物理路径。
- 独立开始/暂停：总览行末按钮作用于该目标；左侧状态卡的开始/停止作用于当前选中目标。全部开始/暂停作用于所有已保存目标。
- 对比：在全部目标勾选最多 4 个目标，点击“对比所选”。相同协议、同一统计截止时刻、同一时间轴与延迟刻度；小时格共用颜色范围。未启用协议、未采样、暂停和本地错误不会伪装成正常或远端故障。
- 目标设置：暂停目标后可以编辑名称/IP/端口/异常判断阈值。修改 IP、协议或 TCP 端口、超时后，详情中的“历史配置”可打开之前的序列。更名不改变历史。
- 移除：保留历史并进入已移除目标列表，可恢复；恢复后默认暂停，且取消自动启动。

同一 IP 可以配置多个 TCP 端口。完全相同的检测序列共享采样和历史，停止其中一个引用不会终止其他引用；同一序列同时运行时需要相同的采样间隔、路由及诊断参数，参数冲突会明确提示，不会静默改变正在运行的检测。ICMP 结果是 IP 级检测，不能区分同一 IP 的两个 TCP 服务。在线注释开关是所有目标共用的应用设置。

## 单目标详情与诊断

- 概览：最新路由摘要及跳数、IP、地区、网络/线路、RTT 五列表格，最新探测结果、近 5 分钟回应率/建连成功率、近 1 小时 P95，以及共用时间范围的折线图和小时格。“更多统计”可展开查看 P50、极值和延迟波动。
- 路由历史：选择最近 200 份快照，查看每跳 IP、回应次数和延迟；可选在线节点注释。更早的关联快照可从事件打开；保留期内完整记录可导出。
- 异常与事件：开始/停止、连续异常与恢复、延迟升高、系统选路改变、采样空档、路径变化；可打开关联的前后路由。
- 导出诊断包：当前统计序列的 CSV、目标参数、路由参数、完整路由/事件 JSON、相关节点当前缓存、路由注释快照与修订，以及解释文本。双协议分别导出，TCP 包包含共享的 ICMP 路由。各文件在生成时读取，持续采样时末尾时间可能略有差异。

## 对照每天的高峰时段

页面顶部统一的 **近 24 小时 / 近 7 天** 同时控制折线与小时格。24 小时每点 5 分钟，7 天每点 30 分钟；显示成功延迟均值、最低/最高范围和失败标记，悬停可看时间及计数。窗口起点向下对齐到分钟，末尾截至实际查询时刻；最后一个区间可能只有少量样本。时间视图最多每 15 秒刷新一次，标明统计截止时间。

小时格按本地日期分行、00—23 时分列。滚动窗口通常横跨 2 或 8 个日期，边缘只有部分小时，范围外保留空位。可以切换 **平均延迟 / 失败比例**，悬停查看详细数值，点击格子在折线图中高亮对应小时。日期跨夏令时变化时，按日期和时区偏移分行，避免重复小时覆盖。灰色表示没有采样，不冒充 0 ms 或 100% 成功。

延迟颜色按当前窗口各小时的均值范围映射，图例显示上下限；比较不同窗口时请同时看数值。失败比例按 0%—100% 映射，全部失败用红色和 × 标记，只有本地错误用独立颜色和 !。颜色只代表已有样本，少量采样不能证明整小时质量。

默认启动后请求路由检查，此后每轮完成后间隔 10 分钟再次请求。所有目标共用一个串行路由队列，等待时间不占探测预算；同一 IP、网络环境和探测策略下的待执行或在途请求可以共享结果。手动和异常诊断优先，每连续处理 3 个优先任务后服务较早的任务，避免定时检查长期等待。多目标积压时，实际完成间隔可能大于配置值；总览和路由详情显示排队状态与快照时间。异常触发额外诊断并有 5 分钟冷却。初测每跳 3 次，发送至少间隔 400 ms，最多 3 个在途调用；默认最多 32 跳、单次超时 1.5 秒、整轮预算 60 秒，超出预算保存实际已发送的部分结果，不把未发送探测算成超时。初测完成后，仅对三次均超时、没有回应的跳进行轮流补测，发送至少间隔 1.2 秒，取得回应即停止该跳补测；初测与补测合计每跳最多 10 次（不是额外 10 次）。补测阶段最多 20 秒，且计入原有整轮预算；节点较多时可能未补满 10 次，详情会说明预算已用尽。已获得回应的 1/3、2/3 节点无需补测来补齐回应率，明确不可达及本地错误不作为普通超时重试。手动检查在监控运行且启用路由时可用。

右上角“统一设置”调整检测间隔、超时、路由间隔/跳数/预算；目标设置中的“异常判断阈值”调整异常/恢复确认次数和延迟阈值。默认成功基线建立后，连续 3 次失败确认异常，连续 3 次成功确认恢复。首次一直无成功结果显示“可达性未验证”，不直接判定离线。

延迟检测需要足够历史：排除最近 5 分钟、至少 60 个成功样本的基线中位数为 B；最近一分钟有足够成功样本的中位数为 M。当 M 超过 `max(1.5 × B, B + 50ms)` 持续 30 秒，记录延迟升高。恢复用较低阈值和持续确认；规则可调整，事件保存采用的参数。

## 如何理解结果

“统一设置”页面的 **在线节点注释** 与 **自动注释新路由** 在全新安装时默认勾选。开启后，通过 HTTPS 向配置的数据源逐个提交未缓存的公网节点 IP，默认使用 **ipwho.is**，显示 ASN、组织、原始 ISP 字段、国家/地区/城市、来源及查询时间。查询服务及缓存说明保留在注释设置中。服务也会看到发起 HTTP 请求的出口 IP；不提交整份路由、监控历史或诊断包。字段缺失时显示未知，服务原文可能是英文。

查询成功在 SQLite 缓存 7 天；相同节点通过共享客户端复用各来源缓存，重启可复用。失败状态缓存 10 分钟，保留最近成功结果；网络故障仅对对应来源退避 1 分钟，HTTP 429 按 Retry-After 暂停并持久保存，认证失败暂停该来源 1 小时。每个来源最多约每 1.2 秒一次、本机滚动 24 小时最多 900 次；服务端可能按共享出口进一步限流。私网、CGNAT、回环、链路本地和特殊保留地址只做离线说明，不向服务提交。

独立选项 **自动注释新路由（托盘隐藏时继续查询）** 控制后台查询。升级会保留旧设置：已关闭的仍关闭，“查看时查询”不自动改为后台模式，旧文件缺少开关时按关闭处理；已有设置损坏或无法读取时也不自动开启查询。后台使用单个工作任务和最多 16 个待处理路由任务，在线补全的排队及请求预算为 20 秒，单请求超时 6 秒；超出预算保存部分注释，后续可手动补全。关闭在线开关或停止监控，会取消在途查询并使已排队任务只使用本地缓存。查看模式离开页面/隐藏窗口时取消在线任务，后台模式可继续处理新路由。

内置 ASN 名称表包括：电信 163 / CN2、联通 4837 / 9929 / 国际 10099、移动 CMI / CMIN2 / 国内网络、CTGNet 等，原始 ASN 仍保留。2.2 加入经过核实的 `59.43.0.0/16 → 电信 CN2` 本地地址段规则，来源为 [APNIC 的 CN2-BB 注册记录](https://rdap.apnic.net/ip/59.43.250.50)，核对日期 2026-09-09。`59.43.250.50`、`59.43.246.178` 即使没有 ASN、没有缓存或关闭在线注释，也能显示“电信 CN2 · IP 地址段匹配（注册归属）”；ASN 仍为未查得，不伪造 AS4809 查询结果。地址段所关联的网络 ASN 仅用于对照名称与提示冲突，不能视为该节点的实测 ASN。

ASN 与地址段指向不同已知网络时并列显示“归属待核对”；有陌生 ASN 时保留其编号并另列地址段归属。每条前缀证据保留范围、注册名称、来源及核对日期，随软件发布更新，不额外联网下载规则。名称只说明节点归属；仅目标命中不会被说成中间路径经过该网络。不认证 CN2 GIA/GT，不把 TTL 节点序列冒充 BGP AS_PATH。

概览路由直接显示五列表格，IP 用等宽字体、RTT 右对齐。默认隐藏非公网节点及整跳未回应的行，保留原始跳数和隐藏数量；公网归属未知的节点仍显示，勾选右上角、详情按钮左侧的“显示全部节点”可还原。目标回应行始终保留，包括私网目标；未探测到目标时明确标明“未到达目标”。直接显示当前筛选结果的全部行，不再限制 6 行或提供“展开其余行”；较长路由使用概览的纵向滚动。

地区使用同一注释快照的城市、省区或国家，城市不依赖 ASN。只有省区或国家时标明粒度，字段缺失保留“地区未知”，不从 ASN/运营商总部/APNIC 联系地址猜城市。相邻行仅在原始 TTL 连续、每跳单一响应、城市明确且城市与网络及证据状态一致时合并；不跨隐藏节点、未知地区、多响应跳或目标行合并。合并行保留跳数范围，多 IP 显示数量并可展开各跳；重复同一 IP 直接显示该 IP。长字段悬停可读完整内容，详情仍保留原始定位和查询时间。地区返回数量不代表真实城市已经验证。

路由表 RTT 是本次路由探测中该 IP 有效回应的平均值，排除超时和诊断错误；它与持续采样的曲线是不同采样轮次。合并行显示各跳均值的最小～最大范围，可展开查看各跳，悬停 RTT 可看原始探测。没有有效 RTT 显示 `—`，原生计时为 0 显示 `<1`，合并范围后的 `*` 表示部分成员没有有效 RTT。范围不代表链路单向耗时，不能用相邻跳 RTT 相减定位拥塞。

每个新路由先保存本地规则及缓存的解释，允许联网时再补全，界面不必等待整轮查询。默认显示最新保存的解释，可勾选“查看最早保存的注释”对照。2.1 旧注释会在打开对应记录或概览读取最新路由时，使用保存的原始证据生成“按当前规则重新解释”修订；无原始注释时标明当前缓存解释。升级重解释本身不联网、不遍历全历史，也不将今天的城市缓存静默写进旧快照。手动补全可按现有查询设置使用新缓存/查询；证据相同不重复保存修订。查询日期、规则版本、解释版本、网络和地区证据随诊断包导出。缓存/城市变化和规则更新不触发线路切换告警。

注释查询独立于探测和告警，失败不影响监控。注释是查询时数据库的估算信息，不是路由发生时的历史归属；地区不能证明节点物理位置，ASN/运营商不能据此确认去程/回程线路。诊断包的 `node-metadata.json` 只导出相关节点的已有缓存，导出本身不发起查询。服务接口参考：[ipwho.is 官方文档](https://ipwhois.io/documentation)。

ICMP 回应率与 TCP 建连成功率各自按有效尝试计算。TCP 成功后立即关闭，不发送业务数据，系统可能重传 SYN，因此它不是裸 SYN 丢包率或业务健康率。

失败 RTT 为空，不用 0 或超时上限参与平均。成功的原生 ICMP RTT 为 0 时显示 `<1 ms`，表示毫秒计时分辨率下的结果。平均/P50/P95 仅使用成功样本；分位数采用 nearest-rank 方法。曲线基于分钟汇总，以 5 或 30 分钟粒度显示均值、范围和失败标记。

延迟波动取最近最多 100 条记录中，同一环境、相邻且成功样本的 RTT 差绝对值的平均，不跨失败或空档计算，不宣称是标准单向抖动。明确的本地权限、资源和参数错误单独计数；不可达记录为访问失败，但不能直接归因于厂家。采样成功比例不等于全天在线时长。

ICMP 无回应不能证明目标离线或已确认禁 Ping；ICMP 正常不代表所有业务正常。只有测试 IP 不能测实际业务吞吐，其路径也未必等于实际业务端点路径。

中间路由器不回复可能是诊断限速，不直接判定链路丢包。每跳保留多个 IP，探测时间和初测/补测标记随原始结果保存及导出。标题统一显示“第 7 跳 · 回应 1/3 · 超时 2 次”；有补测时附上初测及补测的独立回应数，不再显示重复的“未回应”占位行。本地错误保留状态码，不冒充超时。概览新发现的节点标记“补测”，这类行不与初测节点合并。路径变化比较仅使用初测记录，并要求探测策略相同；补测发现的节点用于补全可见性，不触发线路切换判断。未知节点、到达状态变化与路径变化分别记录。候选变化约 30 秒后复测，重复观测且共同节点足够才记录持续路径变化，仍不能证实 BGP 切换或排除负载均衡。每跳 RTT 包含回复路径，不能简单相减认定某段链路耗时。

这里是本地到目标的观测路径，无法得到真实反向路径。异常和路由同时变化只是关联证据。

## 长期运行与数据

终点、路由和写入各自在后台运行；全局最多 32 个在途终点探测，单序列不重叠，初次采样错峰。所有目标共用一个串行路由队列和一个有界数据库写入队列，样本、路由、事件及注释缓存统一写入并批量提交。等待探测资源的时间不计入 RTT；并发不足而跳过的采样记为空档，可在总览状态提示中查看本次跳过数，不计入远端失败。停止会等待有超时上限的在途原生调用完成，通常不超过配置的探测超时，界面保持响应。托盘隐藏时暂停图表查询；长周期统计读分钟汇总。

软件订阅系统路由通知，并每 5 秒复核目标选路；发现相关变化后去抖，取消旧环境路由、重建基线。系统选路信息不能保证揭示全部 VPN/TUN/WFP 重定向。ICMP/TCP 探测不使用 HTTP 代理，系统 VPN/TUN 仍可能影响路径；可选的 HTTPS 节点查询遵循系统 HTTP 代理配置。

不阻止电脑休眠；休眠、暂停、退出期间无法采样。恢复后过期探测丢弃，空档不补造失败或补发请求。要全天采样，运行设备本身需保持运行。

数据位于 EXE 同目录的 `data`：`settings.json`、`history.db` 及 WAL/SHM、`startup.log`、`exports/*.zip`。原始采样、路由和事件保留 31 天，启动及运行期间每分钟执行有界清理，每张表每轮最多删除 2000 行，避免一次长事务阻塞采样。日志按约 1 MiB 轮换，保留一份旧日志；备份和导出不自动删除。SQLite 清理后文件可能保留可复用空间，不每轮强制收缩。

## 保留旧版数据

从 2.4.0 升级到 2.6.0：首次读取单目标设置时，自动生成第一个目标，保留 IP、端口、协议、间隔、超时、自动启动和在线注释选择。配置版本升级为 3；首次写入前保留 `settings.json.before-multi.bak`，新配置通过临时文件落盘后原子替换。损坏或来自更新版本的配置不会被默认值自动覆盖。数据库仍为 v4，只补充清理所需索引，原有历史键与数据保持兼容。

新目录不会自动读取其他目录。完全退出旧版和新版后，将旧版的整个 `data` 目录复制到新版目录。不要在软件运行时仅复制 `.db` 而遗漏 WAL。

首次打开旧数据库会建立一致性备份 `history.db.before-v2.bak`，然后事务迁移。旧设置保留 TCP 模式和启动偏好；旧记录保持独立。旧版未保存的超时和出口参数标记为未知，不拿当前设置冒充。填写原 IP/端口，点击“查看旧版 TCP 历史”。新记录按协议、IP、端口和超时参数隔离；修改参数后应使用相同设置查看相应历史。

历史和诊断包不自动上传。启用节点注释时，在所选的查看/后台模式下向查询服务发送公网节点 IP；全新安装默认启用，升级保留原选择。本版未集成 NextTrace、测速、TCP 业务大包传输或桌面通知服务；基础诊断独立于第三方查询服务。

从 2.0 升级：退出旧版，将整个 `data` 目录复制到新版程序目录后打开；保留原目录以便回退。数据库从 v3 事务迁移到 v4，仅新增注释快照表，采样与历史路由保持原样。旧版不能直接打开迁移后的 v4 数据库。

从 2.1 / 2.2 / 2.3 / 2.3.1 升级到 2.4.0：同样复制整个 `data` 目录。数据库仍为 v4；保留全部采样、路由、首次注释及查询开关，旧记录按需本地重新解释。表格折叠、筛选和 RTT 汇总只影响显示，不修改原始路由。保留旧目录作为回退副本。

## 规模验证

20 个目标同时启用 ICMP + TCP、全部等待 3 秒超时的模拟压力检查通过；验证了并发上限、单独暂停、休眠恢复、路由公平排队、资源不足只记空档及磁盘故障时全局停止。该数量是本次验收规模，不是任意参数下的性能承诺。采样超时大于间隔、设备休眠和资源不足均可能降低实际采样频率。

本机离线生成 20 个目标 × 双协议 × 每 5 秒 × 7 天，共 4,838,400 条记录，数据库约 1.19 GB：20 目标七天总览首次约 499 ms、再次约 451 ms；24 小时总览约 84 ms；单目标详情约 51 ms；40 条并发写入约 18 ms，合并为 2 次提交。这是该机器上的测试结果，未执行 31 天全天持续运行试验。界面实时状态每秒更新，历史查询最多每 15 秒一次，隐藏后停止图表查询。

在线注释共用一个客户端及缓存，查询按队列执行，每份路由获得最多 20 秒执行预算，排队不消耗该预算；仍受单请求超时、最小间隔和每日查询限额约束。查看或停止某个目标不会取消其他目标的后台注释。

## 构建与实现

终点 ICMP 与路由共用 Windows 原生 ICMP 接口。实现时在当前运行时观察到异步 .NET Ping 的句柄积累，最终采用生命周期明确、超时有界的原生调用，不靠定期强制 GC。TCP 保留 Socket.ConnectAsync。

核心在 `src/TcpLatencyMonitor.Core`，桌面在 `src/TcpLatencyMonitor.App`；内部项目名保留以便追踪改造，发布程序为 `IpQualityMonitor.exe`。构建需要 .NET SDK 10、Visual Studio C++ Build Tools 和 Windows SDK：

```powershell
.\test.ps1
.\build.ps1 -Publish
.\package.ps1
```

用 `-Dotnet 'SDK路径\dotnet.exe'` 指定 SDK，`-Packages '完整NuGet缓存目录'` 离线构建。默认 Windows x64 自包含 NativeAOT。验证结果和限制见 `docs/VALIDATION.md`。

桌面结构参考用户提供的 KaringLatencyMonitor，保留 MIT 许可 `LICENSE.reference`。探测与诊断代码独立实现，借鉴 TcpQuality/NetQuality 的思路；名称表及地址段证据记录来源，未移植其脚本、上传服务或脚本运行环境。
